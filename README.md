# xagent

An LLM harness whose context window is a Python REPL.

The interpreter namespace holds the data. The context window holds only the narration
of what was done to it.

```bash
uv run xagent -p codiv "count the .py files under src/ and total their lines"
```

## The idea

Conventional harnesses treat the context window as a transcript of tool calls and
their full results. Every large result — a file, a log, a search — is paid for twice:
once to read it, and forever after to carry it. Compaction then destroys information,
because the transcript *was* the only copy.

xagent inverts that. The model acts by writing Python cells into a persistent IPython
kernel. Large values get bound to variables and shown as one-line handles:

```python
>>> big = read("war_and_peace.txt")
<str 3.2mb, 66,055 lines> _1
The Project Gutenberg eBook of War and Peace
…full value live in `_1` — peek(_1) or slice it
```

Three properties follow, and they are the reason the design is interesting:

**Compaction has a floor of truth.** After summarizing away fifty cells, `df`,
`hits`, and `results` are still exactly correct, so the model can re-derive instead of
trusting a summary. The evicted-span report therefore carries two halves: an LLM
summary of what the *code* did, and a variable table regenerated by introspecting the
live kernel. The table is authoritative; the prose is a lossy sketch. Summaries
describe code and never values — if cell 12 mutated `df`, a value summary written at
cell 40 lies silently, whereas the table cannot.

**Fan-out is nearly free.** Subagents return Python objects, not prose:

```python
hs = [agent(f"audit {f}", seed={"src": read(f)}) for f in files]
results = gather(hs)          # parent context grew by one line
bad = [r for r in results if r and r["issues"]]
```

**The model cannot flood its own context.** Output capping is enforced mechanically
at display time, not requested in a prompt. There are two enforcement points, because
the in-kernel one is bypassable and the harness-side one is absolute.

## Providers

Chosen explicitly with `-p`, not inferred from the model name.

| | `anthropic` | `codiv` |
|---|---|---|
| endpoint | Messages API | `https://api.codiv.ai` (SGLang) |
| default model | `claude-opus-5` | `qwen-3.8-27b` |
| credentials | OAuth token or API key | none required |
| prefix caching | explicit `cache_control` | automatic (radix cache) |
| reports hit rate | yes | no |
| max output | 128k (the API ceiling) | 128k, clamped to the window |
| sampling params | rejected — `temperature` is deprecated | accepted |

```bash
uv run xagent -p anthropic -m claude-sonnet-5 "…"
uv run xagent -p codiv -t high "…"            # thinking:  low | medium | high
uv run xagent -p codiv -s instruct "…"        # sampling:  thinking | instruct
```

Both cache prefixes, by different mechanisms, so the compaction policy below earns
its keep on both. Only Anthropic reports hit rates, so only there is it measurable.

### Output length and sampling

Both backends are configured for a **128,000-token output ceiling**, which is exactly
the Anthropic API maximum — one token more is rejected outright.

They enforce it differently, and the difference matters. Anthropic budgets input and
output separately. SGLang counts `input + max_tokens` against a single 262,144-token
window and rejects the request when they overflow it — so a fixed 128k output would
start failing precisely when a session grew long enough to need compaction. `codiv`
therefore gets a per-request clamp: at a 200k context its output budget drops to
~58k automatically.

Sampling presets follow the Qwen 3.8 recommendations and apply to `codiv` only:

| | temperature | top_p | top_k | min_p | presence_penalty | repetition_penalty |
|---|---|---|---|---|---|---|
| `thinking` (default) | 1.0 | 0.95 | 20 | 0.0 | 0.0 | 1.0 |
| `instruct` | 0.7 | 0.80 | 20 | 0.0 | 1.5 | 1.0 |

`min_p`, `presence_penalty` and `repetition_penalty` have no field in the Anthropic
wire format and ride in `extra_body`. The real Anthropic API rejects all of them, and
rejects `temperature` as deprecated for these models, so it receives none. When
extended thinking is enabled, `temperature`/`top_p`/`top_k` are dropped as well —
thinking fixes the sampling distribution and the API rejects them alongside it.

## The surface the model programs against

```python
read(path, lines=None)     write(path, text)      edit(path, old, new)
ls(path, depth=1)          files(glob, path=".")  grep(pattern, glob="*")
sh(cmd, timeout=120)       peek(x, n=40)

ctx()                      # live token budget and the heaviest cells
note(key, text)            # pin a fact; survives every compaction
compress(mode="evict")     # compact now

agent(prompt, seed=…)      # subagent: own kernel, own context window
gather(handles)            # blocks, preserves input order
done(value)                # finish; value returns to the caller
```

## Compaction

Three tiers, cheapest first:

1. **Display caps** — always on, inside the kernel.
2. **Fold outputs** — drop stdout for old cells, keep the code. Code is dense and
   high-signal and usually says what happened.
3. **Evict a span** — replace it with the summary + variable table described above.

The policy is deliberately reluctant, because **compaction fights prompt caching**.
An append-only transcript gets near-total prefix hits; every edit to an earlier cell
throws that away and costs a full-price re-read. A naive trim-on-every-turn policy is
slower and more expensive than doing nothing. So:

- the most recent `KEEP_RECENT` (10) cells are never touched, keeping the cache-warm
  tail stable;
- a batch must be at least `MIN_BATCH` (6) cells, with a `MIN_GAP` (4) cooldown
  between compactions;
- an eviction that would *grow* the context is reverted — measured, not assumed;
- pinned notes ride the tail rather than the head, so `note()` never invalidates the
  prefix (*pinned* means "survives compaction", not "sits first");
- when the floor (system prompt + task + notes + protected tail) is already at the
  watermark, compaction reports itself stalled instead of churning.

Measured on the Anthropic backend: **79% cache hit rate** over a 9-turn session
(19,328 cached reads against 1,629 fresh input tokens).


`test_regressions.py` exists because a five-way code review found real defects; each
check names the bug it prevents from returning. `test_mechanics.py` covers the layer
below the model: state persistence, display
capping, stdout head+tail elision, the harness-side backstop, timeout and interrupt
recovery, the tool surface, off-transcript control signals, the variable table, and
crossing the process boundary. `test_compaction.py` drives tier-3 eviction with a
real kernel and a real model, and asserts the needle stays recoverable.

## Known sharp edges

- **Compaction destroys what was never bound.** Named variables survive exactly; that
  is the "floor of truth". But shell output, tracebacks, and files read without
  assignment live only in the cells, and eviction removes them — the summary is a
  lossy sketch of those, not a record. The floor is a floor of *shape*, not of
  knowledge. Bind or `note()` anything that matters.
- **Subagent returns are restricted to plain data.** Unpickling executes whatever the
  payload names, in the *caller's* process, so a subagent whose context contained
  untrusted file content could otherwise reach code execution across the isolation
  boundary. Returns are loaded through an allowlisting unpickler; a rich custom
  object will be refused rather than silently executed.
- **cloudpickle is broader than expected.** It serializes `io.StringIO` and even open
  file handles, so the seed check catches genuinely unpicklable values (locks,
  sockets, generators) but cannot catch values that pickle into a *useless* state. The
  failure mode is more often silently-wrong state than a loud error. Prefer passing
  plain data.
- **No durability yet.** There is no journal or snapshot, so a killed kernel loses the
  session. (M4 in the plan.)
- **Local and trusted.** Model-written Python runs with your permissions and `sh()`
  runs arbitrary shell. No sandbox. Do not point this at untrusted input.
- **No baseline harness yet**, so the central claim — fewer tokens per task solved
  than JSON tool calls — is argued but not measured. The read-heavy case flatters
  this design; the write-heavy case is where it could plausibly *lose*, since code is
  never folded and a generated file body is emitted as a literal. Measure that one
  first. (M5 in the plan.)
- **Fan-out is untested at scale.** A `gather()` over many subagents can outlive the
  180s cell timeout; the handles survive an interrupt and can be re-gathered, but
  nothing yet proves the O(1)-context claim at 30 agents.

## Layout

```
src/xagent/
  brief.py     capping reprs + budgeted stdout   — runs inside the kernel
  runtime.py   the model-facing surface           — runs inside the kernel
  kernel.py    jupyter_client wrapper, one per agent
  context.py   cells -> messages, cache breakpoints
  compress.py  fold / evict / variable table
  provider.py  Anthropic-compatible adapter, both backends
  runner.py    the sample -> execute -> append loop
  spawn.py     subagents, cloudpickle seeding
  prompts.py   the system prompt
  cli.py       entry point
```
